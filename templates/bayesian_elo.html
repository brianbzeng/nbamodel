NBA Elo Model - Inner Statistical Workings

This page explains the actual update mechanics used by the app. It is inspired by Bayesian thinking in the sense that ratings evolve by incorporating evidence, but it does not use a conjugate prior or posterior in the code.

Biggest issue

The old title implied Bayesian posterior inference. The model actually uses Elo, logistic win probability, margin-of-victory adjustment, and season regression. That is an update rule, not a posterior calculation.

1. A true conjugate benchmark

This section is included only as a comparison point. It shows what actual Bayesian updating looks like for a single fixed win probability, which is not how the team-vs-team rating system works.

θ ∼ Beta ( α0 , β0 ) y | θ ∼ Bernoulli ( θ ) p ( θ | y ) ∝ p ( y | θ ) p ( θ ) θ | y ∼ Beta ( α0+y , β0+1−y )
This benchmark models a single team's underlying win probability and is shown for comparison. It is not suitable for opponent-specific ratings, which is why Elo is used instead.

2. Initialization at 1500

The app does not sample ratings from a distribution. Every team is initialized at the same baseline rating before any game results are observed.

ri = 1500
Each team is initialized at a common baseline rating of 1500 before any game results are observed.

3. Logistic win probability

The model converts rating differences into a home-win probability with a standard Elo logistic curve.

P ( home win ) = 1 1 + 10 − rhome − raway + h s

The code uses the same relationship through a sigmoid helper, so either notation is fine.

4. Rating update rule

This is the main update step. It is an Elo update, not a Bayesian posterior computation.

Δ = K ⁢ m ⁢ ( y − p ) rhomenew = rhome + Δ rawaynew = raway − Δ m = log ( margin+1 )

The surprise term y - p drives the update. Winning as expected changes ratings a little. Winning or losing in a surprising way changes them more.

5. Season regression

Between seasons, ratings are pulled back toward the baseline so they do not stay locked to one historical run forever.

r i,next season = λ ⁢ r i,end of season + (1−λ) ⁢ 1500
This prevents ratings from becoming permanently anchored to historical performance and allows teams to change over time.

Current parameters

K

Base update strength. Higher values make ratings move faster after each game.

h

Home-court adjustment added to the home team's rating gap before computing win probability.

s

Scale factor in the logistic win probability. It controls how quickly probabilities change as ratings separate.

λ

Season regression factor. Values closer to 1 preserve more of last season's rating; lower values pull harder toward 1500.
