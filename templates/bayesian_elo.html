Inner-Workings

This page explains how the app works behind the scenes: the Elo leaderboard, the home-win predictor, and the data scraping pipeline that feeds both.

1. Elo leaderboard

Every team starts at a rating of 1500. After each completed game, the winner gains rating points and the loser gives them up. Bigger surprises move the ratings more than expected outcomes.

  • Ratings are updated after every completed game.
  • Home court is built into the expected-win formula.
  • Margin of victory scales the update, so blowouts move ratings more than one-point wins.
  • Ratings are regressed between seasons so teams can reset over time.

2. Home-win predictor

The predictor trains on historical completed games and then builds one matchup row from the selected home and away teams. It compares logistic regression and random forest on the same engineered feature set.

  • Season win percentage tracks overall team quality.
  • Team strength blends win rate with average scoring margin.
  • Recent form uses rolling results from the last few games.
  • Rest days measure time since each team last played.
  • Injury features count out, doubtful, questionable, and probable players.
  • Injury impact also weights status severity and estimated absence length.
The app keeps both models visible because linear and tree-based models can value the same features differently on a given matchup.

3. Game scraper

The Basketball-Reference scraper pulls every month page for each requested season so the app gets full regular-season coverage instead of just the opening month.

  • Season-range input lets the app scrape multiple years in one run.
  • Rows are normalized into a consistent game dataset used by the predictor and Elo model.
  • Current-season scrapes stop at the latest completed games so future results never leak in.

4. Injury scraper

Official injury report scraping is powered by nbainjuries. The app can save the latest report, a date range, or a season-based set of reports into CSV files that the predictor can reuse.

  • Latest mode grabs the most recent valid official report.
  • Date-range mode walks day by day and saves whichever report exists for each date.
  • Season-range mode uses the game calendar so injury dates line up with the scraped games.
  • Missing report dates return a clear error or are skipped with a note when appropriate.
  • Cached backend CSVs keep later predictor refreshes much faster than the first full run.
